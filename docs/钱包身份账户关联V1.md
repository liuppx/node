# 钱包身份账户关联 V1

Node 提供账户关联的 challenge/verify 服务，但不拥有钱包身份。关联成功只表示 Node 验证了两个控制证明：Wallet controller 控制 DID，链账户控制者控制地址。

账户关联采用确定性唯一规则：一个 Wallet Identity DID 可以关联多个链账户；同一个 `chainKey + account_id` 在 active 状态下只能归属一个 DID。两台设备如果要使用同一地址代表同一身份，必须恢复同一个 DID；不能在第二台设备用同一私钥新建另一个 DID 后重复验证同一地址。

## API

```text
POST /api/v1/public/identity/account-links/challenge
POST /api/v1/public/identity/account-links/verify
```

V1 使用 EIP-191，支持 `eip155:<chainId>`。签名消息绑定完整 DID、chainKey、checksum address、一次性 nonce、issuedAt 和 expiresAt。Node 验证成功后立即消费 nonce，不能重放。

如果同一地址已经存在其他 active DID 关联，`verify` 必须拒绝并返回 `IDENTITY_ACCOUNT_ALREADY_LINKED`。重复提交同一 DID、同一地址的 active 关联是幂等操作，返回已有记录。

非 EVM 链不能直接提交 EIP-191；后续必须增加对应链的签名域适配器，并保持相同的 proof 语义。

账户关联 challenge、active 关联和凭证记录必须持久化。数据库必须清理历史重复 active 地址关联，并对 active `chain_key + account_id` 建立唯一约束，防止并发写入脏数据。
